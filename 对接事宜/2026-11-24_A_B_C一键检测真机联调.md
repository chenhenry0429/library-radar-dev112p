# DEV112P 一键检测真机联调

2026-11-24 · A 统一监测入口 v0.5.0

A 已完成使用者页面的「开始检测」和「停止检测」。B 的实时采集桥接已合入。Windows 采集电脑配置 ONELAB 窗口与录制控件后，按钮会自动调用 ONELAB 录制。真机仍需确认安装版本可调用的控件、设备连接和第一帧。[采集电脑配置说明](../B_chenhenry0429_雷达与采集/README.md#dev112p-实时联调)。现场链路在同一台采集电脑上运行，顺序为 **DEV112P → B 采集与解码 → C 逐帧识别 → A 本机服务 → 使用者页面**。本机配置中的命令由 A 服务启动。真机验收尚待设备入口就绪。

## 需要交付的文件与接口

| 负责人 | 本轮交付 |
| --- | --- |
| B 采集 | 提供能打开 DEV112P 并持续输出已解码帧的程序或可调用模块、启动方式、依赖、实际端口或设备选择方式，以及现场 `_meta.json`。与 C 确认如何传递单帧、时间、帧号和有效 chirp 掩码，确认设备断开、坏帧及退出时的处理。 |
| C 算法 | 将 B 的实时帧流接到现有 `SeatDetector.feed_dev112p`，交付一个可前台运行的现场入口和匹配的 `_algorithm_online.json`。复用现有九字段结果和串行 POST 回执；每次从帧 0 开始。雷达停止后，现场入口负责释放采集资源。 |
| A 应用 | 在采集电脑将现场入口、meta、algorithm 填入 `radar_device.local.json`，启动本机服务。验证按钮状态、开发者页帧号、实际座位状态、断流及停止重启，并记录程序版本与结果。 |

B 和 C 先确认[帧级接口提案](2026-11-19_B-C帧级接口提案.md)。A 的现场入口沿用 `seconds / recording_start`，时间戳须为采集起点的相对秒且严格递增。B、C 需确认设备或采集程序提供什么时间来源。DEV112P 现场桥接显式启用设备计数推算的名义时间，同时保存主机观察时间。

A 向现场入口注入 `RADAR_A_FRAME_URL`、`RADAR_A_FRAME_TOKEN`、`RADAR_A_META`、`RADAR_A_ALGORITHM`。C 把结果 POST 到环境变量中给出的本机地址，带 `Authorization: Bearer <令牌>`，等到 `accepted_frame_id` 后再发下一帧。两份描述须对应同一 `recording_id`。具体启动配置见 [A 实时入口说明](../A_stone140_应用与业务/README_实时入口.md)。

C 当前在线 v0.1 提供占用，`capabilities.posture=false`。本轮真机先验收单座占用、断流与重启。坐姿提示的真机验收待 C 提供可在线输出的姿态能力和标定流程。

## 真机逐项验收

- [ ] 有设备时点「开始检测」。页面先等待首帧，随后显示「正在检测」，开发者页帧号从 0 开始连续更新。
- [ ] 记录空座、入座、静坐、离座和释放时的实际动作与页面反馈，沿用现有占用阈值。
- [ ] 拔掉设备或中断采集。页面给出中断或退出反馈，座位回到待确认。若在配置的等待时间内未收到首帧，页面提示超时。DEV112P 默认等待 60 秒，通用配置默认为 20 秒。
- [ ] 点「停止检测」后检查采集已停、设备资源已释放。再次开始时从帧 0 接收，页面重新确认座位状态。
