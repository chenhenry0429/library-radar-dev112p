## 1. 为什么由算法需求反推数据层级

规范 v1 已明确约定：

- `raw_data` 不预先硬定形状——ADC、距离谱、点云不是同一种数据；
- B 必须在拿到真实协议后填写 `data_level`、`raw_shape`、`raw_dtype`、`axis_order`、`value_unit` 及 IQ 表示法；
- 保留采集接口实际提供的数据，不额外滤波或删帧；**设备固件本身是否滤波必须如实记录**。

因此 C 的第一项工作就是把 M1 每个特征对数据的要求写成可逐条核对的清单，由 B 持此清单对照设备协议与厂商资料填写。

## 2. M1 特征 → 数据需求矩阵

| M1 特征 | 需要什么数据 | 幅值是否够用 | 慢时间（帧序列）要求 |
|---|---|---|---|
| F1 去背景能量 | 按帧的座位区域距离谱幅值 | 幅值即可 | 每帧一次 |
| F2 相位方差（呼吸微动） | 区域内各距离单元的**复数 IQ** 慢时间序列 | **必须复数（含相位）** | 连续 ≥4 s |
| F3 呼吸频段能量占比（0.1–0.5 Hz） | 同上，做慢时间谱分析 | **必须复数** | 连续 ≥4 s（见 §2.1） |
| F4 大幅运动（经过/起身/坐下） | 帧间能量差分；2dfft/点云速度更好 | 幅值即可 | 相邻帧差分 |
| 区域限定（测角） | 多通道相位差（测角） | 复数 | — |

### 2.1 帧率与窗口的两个量化约束

1. **慢时间采样率**：呼吸频段上沿 0.5 Hz，奈奎斯特要求 >1 Hz；考虑滤波余量与大幅运动检测，**帧率 ≥5 Hz 起步、≥10 Hz 为佳**。`nominal_frame_rate_hz` 必须写入 meta.json 并与 timestamps 实际间隔核对。
2. **频率分辨率**：窗长 T 的可分辨频率约为 1/T。4 s 窗 → 0.25 Hz，只能可靠覆盖 0.25–0.5 Hz 段；要覆盖到 0.1 Hz 需约 10 s 窗。**v0.3 方案**：F3 主检测频段取 0.2–0.5 Hz 配 4–5 s 因果窗，10 s 长窗作为可选增强——列为调参项。

## 3. 候选数据层级对比（v0.3：DEV112P 实况已确认）

| 层级 | 内容 | 能支撑 | 不能支撑 | DEV112P 实况 |
|---|---|---|---|---|
| L1 原始 ADC | chirp × 通道 × 采样点 | 全部特征自算，杂波处理控制权在 C | 工作量与带宽最大 | ✅ 透传固件支持 `dsraw`（按 chirp 逐通道，含"输出降采样间隔"参数） |
| **L2 复数距离谱** | 每帧 range-bin × 通道复数谱 | F1–F4 全部；背景去除自控 | — | ✅ 透传固件支持 `1dfft`（按 chirp 逐通道）——**复数性待 DS10012RN 确认** |
| L2.5 RD 谱 | 距离-多普勒谱 | F4 大幅运动分析 | 慢时间窗口由固件 frame 决定 | ✅ 透传固件支持 `2dfft`（按 frame） |
| L2′ 幅值距离谱 | 仅幅值 | F1、F4 | F2/F3 全部失效 | 若 1dfft 仅幅值则退化为此档【待 DS10012RN】 |
| L3 点云 | x, y, v, SNR 列表 | B0 计数 | 呼吸/静坐微动 | ❌ **DEV112P 无直接点云输出**——B0 基线来源需小组决策（开发工具导出 / 芯片目标列表 / 自 2dfft+CFAR 重建） |

**关键结论（v0.3 更新）**：M1 的数据基础已确认——`1dfft` 距离谱按 chirp、逐通道透传可得，`dsraw` 兜底；**剩余关键开关只有"1dfft 是否复数"**。若仅幅值，F2/F3 不可行，需改用 dsraw 自算带相位的 FFT（UART 带宽允许的前提下）。点云不可得从 M1 风险转为 B0 风险。

## 4. meta.json 填写核对表（C 侧验收标准）

| 字段 | C 的验收要求 |
|---|---|
| `data_level` | 明确枚举：`dsraw` / `1dfft` / `2dfft`（透传类型） |
| `raw_shape` + `axis_order` | 逐轴写明（如 `[frame, chirp, channel, bin]`）与尺寸；**通道轴须保留 chip/通道标识**（chip0 RX0/RX1、chip1 RX0/RX1） |
| `raw_dtype` + `value_unit` | 复数数据写明 IQ 表示法与定点尺度（DS10012RN 定义）；幅值/复数如实标注 |
| `radar_config` | 寄存器配置（regs.txt 来源）、帧率、**降采样间隔**、UART 波特率 921600、固件版本；**固件本身是否滤波必须如实记录** |
| `installation` | 位置、高度、角度、**座位区域定义（距离 + E/H 角度范围）**；测角补偿值（H 面 TX1-RX4 −93°、TX1-RX3 −88°；E 面 TX1-RX1 +10°、TX1-RX4 −55°、TX2-RX3 −16°） |
| `nominal_frame_rate_hz` | 与 timestamps 实际间隔核对，偏差过大记入 capture_notes |
| `source_kind` | measured / synthetic，synthetic 必须如实标注 |
| 其余必填字段 | `schema_version、recording_id、seat_id、subject_id、session_id、capture_start、timestamp_unit、timestamp_origin、capture_notes` 齐全，未知写 null 不猜 |

## 5. 已确认事实（2026-11-03，原理图 + UM10059P Rev.1.9）

- **硬件**：DEV112P = 2×ICL1122（S5 系列 1T2R，ADC 2.5 MHz/16 bit，DSP 超分辨率/滤波/CFAR，QFN32）级联 2T4R MIMO + AT32F403ACCT7（Cortex-M4 @240 MHz，SRAM 96+128 KB）；SoC 配置走 I2C、数据走 SPI（双 MOSI，单路 < 25 Mb/s）；对外 J1 = UART + 5V 供电（峰值 202 mA）；波束 E ±50°/H ±40°，增益 6.5 dBi
- **数据透传**：固件支持 `dsraw` / `1dfft` / `2dfft`；dsraw、1dfft 按 chirp 逐通道（channel 0~3 = chip0 RX0、chip0 RX1、chip1 RX0、chip1 RX1），2dfft 按 frame；UART 921600 bps，传输时间限制公式见 UM 2.16.3（B 采集配置必须核算）
- **MCU 封装协议**（UM 附录 A）：`ICLH`(4B) + Length(2B LE) + Type(1B) + Extra(1B) + Data + `ICLT`(4B)；Type=0x00 芯片数据（Extra=通道/SPI 号），Type=0x80 温度（Extra=芯片序号）；芯片数据格式见 **DS10012RN_ICL1122**（UM 引用，待索要）
- **主/从芯片区分**：数据协议 `cfg_msg` 字段，主芯片=0、从芯片=1（UM 2.16.2）
- **寄存器配置流程**：开发工具生成 → 固件 `Config\radarPara\DEV112P\regs.txt`
- **测角**：通道与补偿值见 §4（M1 区域限定依据）
- **固件工程结构**：App（含 `AlgorithmProcessFun` 自定义算法接口、`StartDataTransfer` 透传接口）/ Config / Driver / Middleware / Project / Script
- 详见同目录《官方信号处理链梳理_v0.2.md》

## 6. 待确认问题（v0.3，较 v0.2 大幅收窄）

**第一优先（`DS10012RN_ICL1122` 文档——UM 明确引用，向厂商索要）：**

1. dsraw / 1dfft / 2dfft 的字节格式与**复数性**（F2/F3 成败关键）
2. `cfg_msg` 字段结构（主/从芯片数据如何区分）
3. 芯片有无目标列表输出（B0 候选来源②）
4. dsraw"输出降采样间隔"语义与片内预处理（FFT 前有无去直流/滤波）

**第二优先（B 实测）：**

5. 毫米波传感器开发工具的数据导出能力（点云？距离谱？格式？）——B0 候选来源①
6. 波形配置最大带宽与距离分辨率（UM 电气测试带宽 24~24.25 GHz → 若 250 MHz 则距离分辨率 ≈0.6 m，区域限定需靠角度维）
7. 按传输公式的帧率-点数-通道组合核算（4 通道全开的上限），产出 G1 采集配置

**B 的自测路径（快于厂商往返）**：用 ONELAB 开发工具连 DEV112P 实测数据导出——一次静坐/空座短采集可同时回答数据格式与 G1 两个问题。

## 7. B → C 交接验收（对照规范第 8 节）

规范原文四条：数组长度一致、时间严格递增、载荷轴与单位明确、配置及来源明确。

C 侧附加自动检查（收到文件即跑）：

- `timestamps` 严格递增、非负、float64；
- `frame_ids` 从 0 起连续递增；
- N 帧 ⇒ `raw_data` 首轴长度 = N；
- meta.json 必填字段齐全，`data_level` 明确（dsraw/1dfft/2dfft）；
- 校验失败按规范报告文件及行号，不自行排序、补造或静默删除数据。
