# 项目结构与阶段规划

## 产品目标和当前基线

场景为图书馆面对面六人桌、同侧座位也由高隔板隔开的自习区，倾向在隔板上缘朝向对应座位安装雷达。产品目标是多个座位同时管理占用，并对通过验证的座位启用个人参考下的粗姿态变化提醒。

设备为 DEV112P。当前公开基线只实现单座文件级离线联调：B 文件归档、C 证据契约、A 状态处理与独立 D 标注约定。开发工具授权、固件和厂家原文资料不纳入仓库；不根据型号猜测电气接线、串口协议、实际帧率或空间分辨能力。

## 模块边界

| 模块 | 负责 | 不负责 |
|---|---|---|
| shared | 数组/JSON/CSV 契约、严格校验、版本升级规则 | 决定分类与业务输出 |
| B | 保留真实载荷、逐帧时间、安装/配置、导出与交付 | 根据期望标签改原始数据 |
| C | 因果特征、存在/姿态证据、质量、个人标定及模型记录 | 业务层 2/3/10/60 秒规则 |
| A | 会话、占用、离座等待、释放、提醒和后续展示 | 从原始雷达重新分类或读取真值 |
| D | 独立真值、按人划分数据集、评价和错误分析 | 将评价标签反向注入 C 的参考段选择 |

## 子模块的交付单位

四个模块以“角色_账号_职责”作为顶层工作目录，分别为 A_stone140_应用与业务、B_chenhenry0429_雷达与采集、C_cy071210_识别算法、D_stone140_标注与评价。每个 README 列出成果、源文件、输入/输出和下一项任务，全组进度见 [成果看板](../WORK_STATUS.md)。

A 的网页实际放在对应工作区的 offline_viewer，C 的文档和演示脚本放在 C 工作区；公共 CLI、状态机和校验器继续保留根目录。旧路径只作兼容，不另复制公共程序。完整映射见 [目录指南](directory-guide.md)。共享契约升级在同一个 PR 中同步上下游、样例和测试。

如后续改为多个独立 GitHub 仓库，应先将 shared 发布为有版本号的依赖，再由 A/B/C/D 固定同一兼容版本。总入口维护仓库链接与组合验收版本，不使用未锁定分支的 Git submodule 作为唯一复现凭据；当前不自动创建这些额外仓库。

## 分阶段验收

1. 文件闭环：28 项现有测试、已提交模拟例子、ZIP 离线解压与读取。
2. B 单座实测：获得协议、明确数据级别/轴/单位、保留真实时间与固件滤波信息，空场/静坐/走动/干扰各成连续采集。
3. C 单座算法：先存在证据，再参考/前倾/后靠；未知与拒识保留行，记录因果窗口和标定来源。
4. D 独立评价：同一人员不跨训练/验证/测试，按实测与模拟分别统计；报告静坐漏检、过道误报及提醒/释放时间误差。
5. A 展示：已有读取离线结果的回放页；继续核对 unknown、pending、复核及 EOF 未完成状态，再研究真实数据联调和后续实时接口。
6. 多座位：先相邻两座的遮挡/串扰与目标归属，再扩展至六人桌、多桌。逐项记录实际占用覆盖数与姿态覆盖数。

## 多座位接口升级条件

v1 的一目录一座位、一段连续时间不变。并发扩展前需另行约定 node_id/table_id/seat_id 关系、时间同步与来源、每个座位的有效证据、断连及冲突状态、原始数据归属和聚合输出。顺序采集的多个单座记录不能作为真实并发效果展示。
