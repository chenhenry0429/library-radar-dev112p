## 1. 公共框架（B0 / M1 共用）

- 统一入口：`python detect.py --recording <recording_id_dir> --algorithm B0|M1 --config <参数文件>`，B0 与 M1 同一接口、配置切换（计划书要求）；**所有阈值放配置文件，不写死在代码里**。
- 输入：`<recording_id>_raw.npz` + `<recording_id>_meta.json`（规范第 4 节）。
- 输出：`<recording_id>_result.csv` + `<recording_id>_algorithm.json`（规范第 5 节）。
- **因果性**：任一行的判决只使用 ≤ 该行 timestamp 的历史数据，不用中心窗口、不用未来帧。滑窗**按 timestamp 推进，不按帧计数**——frame_id 只是归档编号，不代表无丢帧。
- **N 帧 → N 行**：窗口未满、拒识、帧无效也保留该行（按一致性约束填 -1/unknown）。
- **职责边界**：C 不实现入座确认、离座释放、10 秒提醒、冷却（均归 A）。C 内部若有时序平滑，必须写入 algorithm.json。

```
raw.npz + meta.json
      │
      ▼
[输入校验]（N 帧/N 行、时间递增、data_level=dsraw/1dfft/2dfft 明确）
      │
      ▼
[区域限定] 按 installation 座位区域（距离 + E/H 角度，含官方测角补偿值）选定有效单元
      │
      ▼
[B0: 点云计数] 或 [M1: 特征 + 判决]（§2 / §3）
      │
      ▼
[一致性约束自检]（§4 五条，违反即报错）
      │
      ▼
result.csv + algorithm.json
```

## 2. B0：点云计数基线（v0.3：输入来源待小组决策）

⚠️ **DEV112P 无直接点云输出**（透传固件只给 dsraw/1dfft/2dfft），B0 输入来源三候选：

| 候选 | 来源 | 状态 |
|---|---|---|
| ① | 毫米波传感器开发工具导出点云 | B 实测开发工具导出能力 |
| ② | ICL1122 芯片目标列表输出 | 待 DS10012RN 确认协议是否含目标列表 |
| ③ | C 自 2dfft + 标准 CFAR 重建点云 | 可控；但"官方基线"弱化为"标准方法基线"，**需知会教师** |

若 ①② 均不可得 → 小组决策走 ③，并在实验报告中如实说明基线构造方法。

流程（以点云可得为前提）：

```
逐帧点云 → 区域过滤（座位距离/角度范围） → 区域内点数 n_t
  → 阈值判决：n_t ≥ T1 → presence=1；n_t ≤ T0 → presence=0；否则 -1
  → 短窗去抖（多数投票，参数记入 algorithm.json）
  → 写 result.csv
```

- `target_count`：v0.3 输出区域内点数 n_t（presence=1 时为正整数）；不可靠时改 -1。
- `posture`：全部按规则填 `unknown` / `not_applicable`；`calibration_status` = `uncalibrated`。
- **预期缺陷（实验要量化的对象）**：静坐者微动弱 → 点云稀疏或缺失 → 漏检。旁证：矽典微 XenD/P 系列成品（S1/S3/S5 芯片）明确支持静坐/静卧检测，恰说明点云计数基线对静坐的真实风险，正是 M1 要改进的对象。

## 3. M1：区域限定 + 微动特征 + 时序判决

```
1dfft 距离谱【v0.3 确认可得：DEV112P 透传固件支持 1dfft 按 chirp、逐通道（channel 0~3）透传；
  复数性（IQ）与字节格式待 DS10012RN 确认；若仅幅值 → 改用 dsraw 自算带相位 FFT（带宽核算前提下）】
      │
      ▼
(1) 区域限定：按 installation 距离/E-H 角度范围选有效 bins
    【官方测角通道与补偿值：H 面 TX2-RX1、TX1-RX4(-93°)、TX1-RX3(-88°)；
      E 面 TX1-RX1(+10°)、TX1-RX4(-55°)、TX2-RX3(-16°)；距离分辨率待 B 配置确认（~0.6 m 量级则距离维仅粗分）】
      │
      ▼
(2) 背景估计与冻结：
      空闲态（或采集开头若干秒）→ 持续更新背景谱
      一旦判决非空闲 → 冻结背景更新，直到回到空闲
      （目的：防止静坐者被缓慢吸收为背景）
      【v0.3 定性：透传数据位于片上 DSP 目标检测之前，背景去除控制权在 C，不受固件 MTI 制约】
      │
      ▼
(3) 特征提取（约 4s 因果滑窗，按 timestamp 推进）：
      F1 去背景能量
      F2 区域内 bins 相位方差（慢时间）【依赖 1dfft 复数性】
      F3 呼吸频段能量占比（主检测 0.2–0.5Hz，窗长/频段为调参项）
      F4 大幅运动特征（帧间能量差分 → 区分经过/起身/坐下）
      │
      ▼
(4) 帧级判决：F1–F4 组合打分 + 双阈值滞回；证据不足 → presence=-1
      │
      ▼
(5) 因果平滑：短窗去抖（方式与参数写入 algorithm.json）
      │
      ▼
(6) 输出 result.csv
```

## 4. 输出契约映射（result.csv 逐列）——已实战验证、视为冻结基线

> **2026-11-03 实战验证**：本节契约产出的 lifecycle 演示数据（outputs/offline_demo/，synthetic 走同一接口）已被 A 端成功消费、运行正常；A 端确认**后续保持该接口**。正式 B0/M1 实现的输出必须与本节逐列一致；任何变更（加列、改枚举、改空值约定）须经小组协商，不得单方面修改。

| 列 | B0 / M1 填法 | 约束要点 |
|---|---|---|
| frame_id / timestamp | 原样复制 B 的 frame_ids / timestamps | 逐一匹配；timestamp 保证 float64 往返精度 |
| presence | 判决结果 -1/0/1 | -1 未知；0 区域确认无人；1 区域确认有人 |
| presence_confidence | 判决置信分数 [0,1] | presence=-1 时为空；不保证是校准概率 |
| target_count | B0：区域内点数；M1：v1 可先输出 1 或 -1 | presence=0 ⇒ 0；presence=-1 ⇒ -1；不可靠不强填 |
| posture | v1 一律 unknown / not_applicable | presence=0 ⇒ not_applicable；其余 unknown |
| posture_confidence | v1 一律空 | unknown/not_applicable 时为空 |
| calibration_status | v1 一律 uncalibrated | 姿态能力上线后扩展 |
| quality | ok / low_signal / invalid_frame | 非 ok ⇒ presence=-1、posture=unknown、两个置信度为空 |

**输出前五条一致性自检**（实现为断言，违反即报错，不发坏文件）：

1. presence=0 ⇒ target_count=0、posture=not_applicable
2. presence=-1 ⇒ target_count=-1、posture=unknown
3. presence=1 ⇒ target_count 为正整数或 -1
4. quality≠ok ⇒ presence=-1、posture=unknown、两置信度为空
5. calibration_status≠valid 且有人 ⇒ posture=unknown

《CSV格式示例》的 5 行样例可直接用作输出模块的单元测试用例（覆盖 low_signal、invalid_frame、calibrating 等合法组合）。

## 5. algorithm.json 计划（M1 示例）

| 规范必填字段 | v0.3 填法 |
|---|---|
| schema_version / recording_id | 按规范 |
| algorithm_version | `M1@0.1`（B0 同理 `B0@0.1`） |
| parameter_version | 参数文件内容哈希前 8 位 |
| 支持能力 | presence=true, posture=false（v1） |
| 配置及阈值 | 内嵌生效参数全文（含 F1–F4 权重、双阈值、去抖参数） |
| 窗口时长 | 各特征各自窗长（F2/F3 约 4–5s，F4 帧间） |
| 时序平滑方式 | 去抖方法 + 参数 |
| 模型版本 | `rule-based`（无学习模型） |
| calibrations | v1 空列表 `[]` |

## 7. synthetic 先行开发路径

规范第 6 节允许模拟数据走同一接口（`source_kind=synthetic`）。因此 M1 可先在**合成复数距离谱**（空场景 + 呼吸调制 + 大幅运动扰动）上开发特征提取、判决与输出模块，并用 CSV 示例的合法组合做接口自测；真实数据到位后仅替换输入，不改处理链路。建议作为 G1 之前的并行准备，避免算法端空等硬件。
